# PTS Demo - Deployment Guide

This document covers two deployment paths:
1. **Free-Tier Cloud Demo Deployment (Render.com)** — Free hosting ready for public evaluation with zero server management.
2. **Dedicated Production Deployment (Ubuntu VPS)** — High-performance deployment with Docker or systemd.

---

## Part 1: Free-Tier Cloud Deployment (Render.com)

PTS Demo includes built-in support for free-tier cloud deployment using **Render Blueprints** (`render.yaml`).

### Architecture Overview
- **Web App**: Flask + Gunicorn WSGI (`gunicorn wsgi:app --workers 2 --threads 4 --timeout 120`).
- **Database**: Render Free PostgreSQL database (auto-wired via `DATABASE_URL`).
- **Bot Engine**: Webhook mode embedded within Flask (`POST /webhook/telegram`).
- **Health Checks**: `/health` endpoint returning JSON status.
- **Auto-Registration**: Registers its own webhook with Telegram on startup using `RENDER_EXTERNAL_URL`.
- **Demo Mode**: Automatically creates tables and seeds realistic Ethiopian test data and a read-only CEO account (`demo_ceo`).

---

### Step-by-Step Deployment Instructions

#### Step 1: Create a Telegram Bot
1. Open Telegram and search for **@BotFather**.
2. Send `/newbot`, choose a name and username (e.g. `pts_demo_bot`).
3. Copy the HTTP API token (e.g. `123456789:ABCdefGHIjklMNOpqrsTUVwxyz1234567`).

#### Step 2: Push Repository to GitHub / GitLab
Ensure your project contains:
- `render.yaml` (Render blueprint)
- `Procfile`
- `requirements.txt` (with `gunicorn` and `psycopg2-binary`)

#### Step 3: Deploy Blueprint on Render
1. Sign up or log into [Render.com](https://render.com).
2. From the dashboard, click **New +** and select **Blueprint**.
3. Connect your repository.
4. Render will read `render.yaml` and configure:
   - **Web Service**: `pts-demo` (Python runtime, free tier)
   - **PostgreSQL Database**: `pts-demo-db` (free tier)
5. Under Environment Variables:
   - `TELEGRAM_BOT_TOKEN`: Paste your token from @BotFather.
   - `DEMO_MODE`: Set to `true` (default in `render.yaml`).
   - `SECRET_KEY`: Automatically generated by Render.
   - `TELEGRAM_WEBHOOK_SECRET`: Automatically generated by Render.
   - `DATABASE_URL`: Automatically linked to `pts-demo-db`.
6. Click **Apply**. Render will provision the database, build the web service, install dependencies, and launch Gunicorn.

#### Step 4: Verify Deployment
1. Open your Render web service URL (e.g., `https://pts-demo.onrender.com`).
2. You will see the **Demo environment** banner across the top.
3. Test the health endpoint: `https://pts-demo.onrender.com/health` (returns `{"status": "ok", "database": "healthy", "demo_mode": true}`).
4. Open your Telegram bot and send `/start`. The bot responds immediately!

### Free-Tier Limitations & Mitigations

| Limitation | Impact | Mitigation / How PTS Demo Handles It |
| :--- | :--- | :--- |
| **Inactivity Sleep** | Free web instances spin down after 15 minutes of idle time. | Incoming HTTP requests (including Telegram webhook calls) wake up the service. Cold starts take **30 to 50 seconds**. To prevent sleeping, set up a free monitor (e.g. [UptimeRobot](https://uptimerobot.com) or [Cron-Job.org](https://cron-job.org)) to ping `https://your-app.onrender.com/health` every 10 minutes. |
| **Database Expiration & Ephemeral Disks** | Render's free PostgreSQL tier expires after 30 days. If using SQLite, file storage is ephemeral and resets on each deploy/restart. | **Auto-seeding on Startup**: When `DEMO_MODE=true`, the application checks if the database is empty upon startup. If empty, it automatically executes `db.create_all()` and populates the complete demonstration dataset and demo accounts. |
| **Public Vandalism** | Anyone with the public demo link can access the admin dashboard. | **Read-Only Demo CEO**: Visitors can log in as `demo_ceo` (password: `DemoCEO123!`). All overview cards, sales analytics, employee tables, and audit logs are visible, but all mutation actions (`POST`, `PUT`, `DELETE`) are blocked with a user-friendly notice. |
| **Local Development Parity** | Webhooks in production must not break local development. | Local developers can leave `DATABASE_URL` unset (defaults to `pts_demo.db` SQLite) and run `python bot/main.py` in polling mode. `main.py` automatically overrides any webhook and runs polling locally. |

## Part 2: Dedicated Production Deployment (Ubuntu VPS)

## 1. Initial Server Hardening & Preparation

Connect to your VPS as `root`:
```bash
ssh root@YOUR_SERVER_IP
```

### Update Packages and Create Non-Root User
```bash
apt update && apt upgrade -y
apt install -y git curl ufw fail2ban

# Create a dedicated sudo user (e.g. deployer)
adduser deployer
usermod -aG sudo deployer

# Setup UFW Firewall
ufw default deny incoming
ufw default allow outgoing
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
```

Switch to your deployer user:
```bash
su - deployer
```

## 2. Deployment Method A: Docker Compose (Recommended)

Docker isolates the application and ensures dependencies and background workers run identically to production standards.

### Install Docker & Compose Plugin
```bash
# Install Docker official convenience script
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
newgrp docker
```

### Clone and Configure PTS Demo
```bash
# Clone repository
sudo mkdir -p /var/www/pts-demo
sudo chown -R $USER:$USER /var/www/pts-demo
git clone https://github.com/your-username/pts-demo.git /var/www/pts-demo
cd /var/www/pts-demo

# Create production environment file
cp .env.example .env
nano .env
```

**Fill in production `.env` settings:**
```ini
FLASK_ENV=production
FLASK_DEBUG=0
SECRET_KEY=GENERATE_A_64_CHAR_HEX_KEY_HERE
DATABASE_URL=sqlite:////app/instance/pts_demo.db
TELEGRAM_BOT_TOKEN=YOUR_LIVE_TELEGRAM_BOT_TOKEN_FROM_BOTFATHER
SESSION_COOKIE_SECURE=True
SESSION_COOKIE_HTTPONLY=True
SESSION_COOKIE_SAMESITE=Lax
```
*(Generate a secret key with: `python3 -c "import secrets; print(secrets.token_hex(32))"`)*

### Seed Initial Admin & Build Containers
```bash
# Build and run containers in detached mode
docker compose up -d --build

# Create initial CEO administrator account inside the container
docker compose exec web python scripts/create_admin.py

# (Optional) Seed demonstration dataset
docker compose exec web python scripts/seed_data.py
```

Check running container status:
```bash
docker compose ps
docker compose logs -f web
```

## 3. Deployment Method B: Native Systemd (Alternative to Docker)

If you prefer running natively on Ubuntu without Docker:

### Install Python 3.12 and Virtualenv
```bash
sudo apt update
sudo apt install -y python3-pip python3-venv sqlite3 nginx certbot python3-certbot-nginx

sudo mkdir -p /var/www/pts-demo
sudo chown -R $USER:$USER /var/www/pts-demo
git clone https://github.com/your-username/pts-demo.git /var/www/pts-demo
cd /var/www/pts-demo

# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# Setup production environment
cp .env.example .env
nano .env

# Initialize database
python scripts/create_admin.py
python scripts/seed_data.py

# Ensure correct web server ownership
sudo chown -R www-data:www-data /var/www/pts-demo
```

### Install and Enable Systemd Services
```bash
# Copy systemd unit files
sudo cp deploy/pts-web.service /etc/systemd/system/
sudo cp deploy/pts-bot.service /etc/systemd/system/
sudo cp deploy/pts-backup.service /etc/systemd/system/
sudo cp deploy/pts-backup.timer /etc/systemd/system/

# Reload systemd and start services
sudo systemctl daemon-reload
sudo systemctl enable --now pts-web.service
sudo systemctl enable --now pts-bot.service
sudo systemctl enable --now pts-backup.timer
```

Verify service status:
```bash
sudo systemctl status pts-web
sudo systemctl status pts-bot
sudo systemctl list-timers --all
```

## 4. HTTPS & Reverse Proxy Configuration (Nginx)

Gunicorn runs on internal port `127.0.0.1:5000`. Nginx terminates SSL/TLS and proxies incoming requests.

```bash
# Copy Nginx site configuration
sudo cp deploy/nginx.conf /etc/nginx/sites-available/pts-demo

# Update your domain name
sudo nano /etc/nginx/sites-available/pts-demo
# Replace 'demo.yourdomain.com' with your actual registered domain name

# Enable site
sudo ln -s /etc/nginx/sites-available/pts-demo /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default

# Test Nginx configuration syntax
sudo nginx -t

# Obtain free Let's Encrypt SSL Certificate
sudo certbot --nginx -d demo.yourdomain.com

# Reload Nginx
sudo systemctl reload nginx
```

## 5. Telegram Bot: Polling vs. Webhook Mode

### Polling Mode (Default)
In default polling mode (`python bot/main.py`), the bot connects outbound to Telegram's cloud API over HTTPS. 
- **Advantage**: Requires zero public open ports, zero webhook SSL setup, and operates smoothly behind NAT firewalls.
- **Maintenance**: Handled automatically by `docker compose` or `pts-bot.service`.

### Webhook Mode (High Volume Traffic)
If your sales transactions exceed hundreds of messages per minute, you can configure Telegram to send incoming messages directly to your server:

1. In your Flask app, expose an endpoint `/telegram-webhook`:
   ```python
   @app.route("/telegram-webhook", methods=["POST"])
   def telegram_webhook():
       # Validate secret token header: X-Telegram-Bot-Api-Secret-Token
       update = Update.de_json(request.get_json(force=True), bot)
       asyncio.run(application.process_update(update))
       return "OK", 200
   ```
2. Register the webhook with Telegram:
   ```bash
   curl -F "url=https://demo.yourdomain.com/telegram-webhook" \
        -F "secret_token=YOUR_SECRET_TOKEN" \
        https://api.telegram.org/bot<YOUR_TOKEN>/setWebhook
   ```

## 6. Daily Backup Verification & Log Inspection

- **Inspect backup timer status**:
  ```bash
  sudo systemctl status pts-backup.timer
  ```
- **Inspect web access & error logs**:
  ```bash
  sudo journalctl -u pts-web -n 50 --no-pager
  ```
- **Inspect Telegram bot activity**:
  ```bash
  sudo journalctl -u pts-bot -n 50 --no-pager
  ```

  ```bash
  ls -lh /var/www/pts-demo/backups/
  ```
